# 장애·오류 분석

1. 학습자에게 **사실 3가지**를 받는다 (없으면 묻는다):
   - 실행한 정확한 명령 또는 조작
   - 오류 메시지 전문 (잘라내지 말 것)
   - 기대했던 결과
2. **debugger 서브에이전트**에게 위 사실과 현재 주차를 넘긴다. 에이전트는 사실/가설 표와 확인 명령을 돌려준다.
3. 확인 명령은 **학습자가 직접 실행**하고 결과를 붙여넣게 한다. 한 번에 하나씩.
4. 원인이 확정되면:
   - 최소 수정 diff 를 보여주고 학습자가 적용
   - `docs/errors/YYYY-MM-DD-제목.md` 를 `docs/errors/TEMPLATE.md` 형식으로 작성 (Claude 가 작성해도 됨 — 기록은 코치의 일)
   - 재발 방지 테스트 1개를 test-writer 에이전트에 요청할지 물어본다
5. 마지막에 **"이 오류를 다음에 혼자 찾으려면 어디를 먼저 봐야 하는가"** 한 줄을 학습자에게 묻고 답을 기록에 넣는다.
