# 개념 설명

대상: `$ARGUMENTS` (없으면 묻는다). 현재 주차(`docs/progress.md`)를 확인해 설명 깊이를 맞춘다.

## 출력 순서 (고정, 각 항목 3~6줄)

1. **개념** — 한 문장 정의 + 비유 1개. 학습자는 신호처리·수식에 익숙하므로 가능하면 그쪽 비유를 쓴다 (예: 토큰 임베딩 ↔ 배열 조향 벡터, attention ↔ 가중합·상관).
2. **왜 필요한가** — 이것이 없으면 무엇이 안 되는가.
3. **요청/데이터 흐름** — 입력 → 처리 → 출력을 화살표 한 줄로. tensor 면 shape 를 함께 (B, T, C).
4. **최소 코드** — 10~20줄. 라이브러리 없이 되면 없이. 각 줄에 짧은 주석.
5. **실행 방법** — 정확한 명령 1~2줄과 어느 폴더에서 실행하는지.
6. **예상 결과** — 실행하면 화면에 무엇이 찍혀야 하는가 (실제 값으로).
7. **흔한 오류 2개** — 오류 메시지 원문 일부 + 원인 + 고치는 법.
8. **확인 문제 1개** — 코드를 한 줄 바꿔서 결과를 예측하게 하는 문제. 답은 학습자가 말한 뒤에 준다.

## 수식이 있는 경우 (4번 앞에 삽입)

- **정의**: 기호와 가정
- **유도**: 등호 한 줄마다 사용한 법칙
- **손계산**: 2×2 행렬, 2~3 토큰, logits 3개 수준으로 실제 숫자 계산
- **수치 검증**: analytic 결과 vs finite difference / brute force 를 코드로 비교
- **반례·한계**: 빈 입력, 0, 매우 큰 값에서 어떻게 되는가

## 마무리

- `docs/glossary/README.md` 에 추가할 한 줄 정의를 제안한다 (학습자가 자기 말로 고쳐 쓰도록).
- 설명이 끝나면 "직접 쳐 보고 결과를 알려 달라"로 끝낸다. 다음 개념으로 먼저 넘어가지 않는다.
