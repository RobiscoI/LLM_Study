# 코드 리뷰

`code-reviewer` 에이전트를 띄운다.

## 대상

인자로 파일·디렉토리를 받는다 — `/review apps/api/routers/chat.py`.
없으면 **작업 트리의 변경분**(`git diff`, staged 포함)을 대상으로 한다.
변경이 없으면 최근 주차 노트의 5절 코드 위치를 본다.

## 검토 순서

1. 기능 정확성 → 2. 데이터 흐름 → 3. 비동기 처리 → 4. 보안 →
5. 오류 처리 → 6. 테스트 가능성

## 출력 형식

```
1. 가장 위험한 문제
2. 원인          (증상이 아니라 기전)
3. 최소 수정 diff (리팩터링 끼워넣지 않는다)
4. 추가 테스트    (이 문제를 잡아냈을 테스트)
5. 확인 질문      (이해했는지 묻는 1~2개)
```

지적에는 **재현 시나리오**를 붙인다 — "입력이 X 일 때 Y 가 되어 Z 로 실패한다".
못 쓰겠으면 추측이므로 그렇게 표시한다.

## 보안은 22주차 전에도 본다

prompt injection · secret 유출 · XSS · CSRF · SQLi · 권한 · 도구 호출 검증.
**LLM 출력은 신뢰할 수 없는 입력이다** — 도구 인자·SQL·HTML·쉘로 가는 경로를 확인한다.

## 이후

지적받은 것은 **직접 고친다.** 수정 diff 를 그대로 붙여넣지 말고 왜 그렇게 되는지
이해한 뒤 자기 손으로 고치고, 5번 확인 질문에 답한다.

고친 오류는 주차 노트의 「오류 기록」 표에 남긴다 (매주 체크리스트 5번).
