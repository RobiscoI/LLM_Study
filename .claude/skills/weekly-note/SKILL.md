# 주차 노트 생성

`docs/weekly/W<NN>_<주제>.md` 를 만든다. 형식은 로드맵의 선수 주차 페이지가 기준이다
(`refs/notion/선수주차_원문_20260923.md`).

## 1. 주차 정보 채우기

`docs/ROADMAP.md` 의 24주 표에서 해당 주차 행을 읽어 **개념·실습·완료 기준**을
그대로 가져온다. 임의로 지어내지 않는다.

파일명 주제는 표의 주제를 쓴다 — 예: `W08_Attention_Transformer.md`.

## 2. 9절 뼈대

`docs/weekly/_TEMPLATE.md` 를 복사해서 1·6·7·8절을 로드맵 값으로 채우고,
나머지는 **빈 칸으로 둔다.** 학습자가 채우는 것이 학습이다.

| 절 | 생성 시 | 채우는 사람 |
|---|---|---|
| 1 선수지식·핵심 질문 | 로드맵 개념에서 핵심 질문 1개 도출 | — |
| 2 이론 | 빈칸 | 학습자 (내 말로) |
| 3 수식·유도 | 빈칸 | 학습자 |
| 4 눈으로 이해하기 | mermaid 코드펜스만 | 학습자 |
| 5 직접 구현 | 빈칸 | 학습자 |
| 6 검증 계획 | 표 머리 + 로드맵 완료 기준 1행 | 학습자가 행 추가 |
| 7 미니 프로젝트 | 로드맵 실습 항목 | — |
| 8 완료 체크리스트 | 6항목 고정 | 학습자가 체크 |
| 9 이해 확인 | 빈칸 | 학습자 (주 끝에) |

**2·3·5 절을 미리 채우지 않는다.** 채워주면 노트가 아니라 교재가 되고, 로드맵의
"내 말로 바꾼다"가 무너진다.

## 3. 파일이 이미 있으면

**덮어쓰지 않는다.** 기존 노트를 보여주고 이어서 쓸지 묻는다.

## 4. 생성 후

- 해당 주차가 **포트폴리오 관문**(4·10·14·16·20·24)이면 노트 머리에 그 사실과
  요구 수준(4수준 이상)을 적는다.
- 코드가 들어갈 자리를 안내한다: 1~6주는 `labs/w<NN>/`, 7~9주는 `llm-from-scratch/`,
  10주~ 는 `apps/api` · `apps/web`.
