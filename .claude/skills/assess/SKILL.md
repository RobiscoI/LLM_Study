# 이해도 판정

로드맵의 5수준 척도로 **현재 주차 주제**에 대한 이해도를 판정한다.

| 수준 | 판정 |
|---|---|
| 1 기억 | 용어를 정의한다 |
| 2 이해 | 왜 필요한지 자신의 말로 설명한다 |
| 3 적용 | 예제 없이 작은 기능을 구현한다 |
| 4 분석 | 로그와 통신 흐름으로 오류를 찾는다 |
| 5 설계 | 보안·비용·성능 trade-off 를 근거로 선택한다 |

## 진행

### 1. 대상 확정

인자로 주차를 받는다 (`/assess 8`). 없으면 `docs/progress.md` 의 현재 장을 쓴다. 기록 대상은 `docs/weeks/week-NN.md` 다.

### 2. 수준별 문제 — 아래에서 위로

**2수준부터 시작한다.** 1수준(용어 정의)은 2수준 답에서 자연히 드러난다.

| 수준 | 문제 형태 |
|---|---|
| 2 | "왜 X 가 필요한가. X 없이 하면 무엇이 깨지는가" |
| 3 | 작은 구현 과제. **참고 없이**, 10~15분 분량 |
| 4 | 고장난 로그·코드를 주고 "어디가 문제인가" |
| 5 | 선택지 2개를 주고 "무엇을 고르고 왜인가. 무엇을 포기하는가" |

한 수준에서 막히면 **거기서 멈춘다.** 위 수준을 더 물어보지 않는다.

### 3. 채점 기준

- **2수준**: 교재 문장을 되풀이하면 미달. 자기 말이어야 한다.
- **3수준**: 돌아가는 코드를 참고 없이 썼는가. 문법 오류는 감점 아니고,
  **구조를 못 떠올리면** 미달.
- **4수준**: 증상이 아니라 **기전**을 짚었는가. "CORS 문제"는 미달,
  "프리플라이트가 401 이라 본 요청이 안 나갔다"는 통과.
- **5수준**: trade-off 의 **양쪽**을 말했는가. 장점만 나열하면 미달.

### 4. 출력

```
현재 수준 : N
근거      : <통과한 문제와 답의 핵심, 막힌 지점>
요구 수준 : 3 (일반) / 4 (관문 주차 4·10·14·16·20·24)
판정      : 통과 / 미달
다음 행동 : <미달이면 무엇을 하면 되는지>
```

주차 노트 마지막의 **완료 판정** 표에 기록한다.

## 미달일 때

**다음 주차로 넘어가지 말라고 분명히 말한다.** 로드맵의 진도 조정 규칙을 제안한다:

- Python 이 처음이면 0~4장의 변수·함수·파일·요청 흐름을 스스로 설명하고 재현할 때까지 반복
- 수학에서 막히면 증명 대신 작은 수·tensor shape 검증 (`/verify`)
- 한 장에 필요한 기간을 자유롭게 쓰고, 막힌 선행 개념으로 돌아가 보완
