# 주차 마감

## 1. 체크리스트 7항목 — 실제로 확인한다

로드맵의 매주 반복 체크리스트다. **물어보지 말고 저장소에서 확인**한 뒤,
확인할 수 없는 것만 묻는다.

| # | 항목 | 확인 방법 |
|---|---|---|
| 1 | 핵심 개념을 내 말로 5문장 정리 | 주차 노트 2절이 채워졌는가 |
| 2 | 예제를 직접 입력하고 실행 | 5절에 코드와 실행 결과가 있는가 |
| 3 | 미니 프로젝트 또는 기능 완료 | 7절, 그리고 실제 코드 파일 |
| 4 | 테스트와 예상 결과 기록 | 6절 표가 채워졌는가. 테스트 파일이 있는가 |
| 5 | 오류 원인과 해결 과정 기록 | 「오류 기록」 표 |
| 6 | Git 커밋·README 업데이트 | `git log` 로 이번 주 커밋 확인 |
| 7 | 다음 주 질문 3개 작성 | 「회고」 |

## 2. 미달 항목 처리

미달이 있으면 **그 사실을 먼저 분명히 말한다.** 특히:

- **4번(테스트)이 비면 주차를 닫지 않는다.** 로드맵의 완료 조건이
  "설명 가능 + 코드 실행 + **테스트** + 화면/로그 + README" 다.
- **5번(오류 기록)이 비면** 오류가 없었던 것인지 기록을 안 한 것인지 확인한다.
  한 주 내내 오류가 없었다면 대개 너무 쉬운 것만 한 것이다.

## 3. 회고 정리

주차 노트의 「회고」를 채운다.

- **잘된 것** — 구체적으로. "이해했다"가 아니라 "예제 없이 causal mask 를 다시 짤 수 있다"
- **막힌 것** — 해결됐으면 어떻게, 안 됐으면 무엇이 남았는지
- **다음 주 질문 3개** — 다음 주차 개념을 미리 보고 만든다

## 4. 완료 판정

`/assess` 를 이어서 돌리도록 안내한다. 이해도 수준을 노트 마지막 표에 적는다.

| 주차 | 요구 수준 |
|---|---|
| 일반 | 3수준 (예제 없이 작은 기능 구현) |
| 관문 4·10·14·16·20·24 | 4수준 (로그와 통신 흐름으로 오류를 찾는다) |

**요구 수준 미달이면 다음 주차로 넘어가지 말라고 분명히 말한다.**
대신 로드맵의 진도 조정 규칙을 제안한다 — 해당 주차를 2주로 늘리거나,
막힌 것이 수학이면 작은 수·tensor shape 검증으로 우회한다.

## 5. 커밋

체크리스트 6번이 미완이면 커밋 메시지를 제안한다:

```
W<NN> <주제> — <핵심 산출물>

<무엇을 구현했고 무엇을 검증했는지 2~3줄>
<막힌 것과 다음 주 질문>
```
