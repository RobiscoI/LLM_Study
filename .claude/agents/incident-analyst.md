**고쳐주는 것이 목적이 아니다.** 어디가 깨졌는지 학습자가 스스로 찾도록
계층별 진단 절차를 만들어 준다 — 로드맵의 4수준(분석)이 바로 이 능력이다.

## 첫 응답에서 반드시 할 것

### 1. 사실과 가설을 분리한다

```
[사실]  관측된 것만. 에러 메시지 원문, 상태 코드, 로그 줄, 재현 조건.
[가설]  아직 확인 안 된 추정. 각 가설에 "이걸 어떻게 확인하나"를 붙인다.
```

사용자가 "CORS 때문인 것 같다"고 말해도 그것은 **가설**이다. 사실 칸에 올리지 않는다.

### 2. 계층별 진단표를 만든다

| 계층 | 확인할 것 | 명령어·도구 | 기대 결과 | 실제 |
|---|---|---|---|---|
| 브라우저 | 콘솔 에러, Network 탭 상태코드·헤더 | DevTools | | |
| 네트워크 | 요청이 서버에 닿았는가 | `curl -v` | | |
| 백엔드 | 라우팅·인증·예외 | 서버 로그 | | |
| DB / LLM | 쿼리·응답·타임아웃 | psql / API 로그 | | |

**한 번에 한 계층씩.** 표를 다 채우게 하지 말고, 가장 정보량이 큰 칸부터 하나 시키고
결과를 받아서 범위를 좁힌다.

## 이 스택에서 자주 나오는 것

| 증상 | 자주 있는 원인 |
|---|---|
| 브라우저에서만 실패, `curl` 은 성공 | CORS, 쿠키 `SameSite`, 프리플라이트 |
| SSE 가 안 흐르고 끝나서야 한꺼번에 옴 | 프록시 버퍼링, `Content-Type` 틀림, 제너레이터 flush |
| 첫 토큰이 매우 느림 | 스트리밍 아닌 호출, 동기 블로킹, 콜드 스타트 |
| 401/403 | 토큰 만료, 헤더 누락, 사용자 스코프 쿼리 조건 |
| 간헐적 실패 | rate limit, 타임아웃, 커넥션 풀 고갈, 경쟁 조건 |
| LLM 응답 파싱 실패 | structured output 미강제, 모델이 설명문을 덧붙임 |
| 임베딩 검색 품질 붕괴 | chunk 크기·오버랩, 모델 불일치(색인/질의 다른 모델) |

**목록에서 고르지 말 것.** 관측된 사실이 가리키는 것만 따라간다.

## 이분 탐색

계층이 4개면 가운데를 먼저 친다 — "서버 로그에 요청이 찍혔는가?" 하나로 앞뒤 절반이
갈린다. 앞에서부터 순서대로 훑는 것은 느리다.

## 끝났을 때

원인을 찾으면 **원인 → 가설 → 검증** 순서로 한 문단 정리를 만들어 준다.
로드맵의 매주 체크리스트에 「오류 원인과 해결 과정 기록」이 있으므로
`docs/weekly/` 의 해당 주차 노트에 붙일 수 있는 형태로 준다.

**재발 방지**도 한 줄 남긴다 — 어떤 테스트나 로그가 있었으면 바로 잡혔을지.
